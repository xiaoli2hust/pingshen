# 全站前端与 UI 新方案：「审图台」

日期：2026-10-25
范围：`review-platform/public/` 的样式和渲染层（`style.css`、`index.html`、`app.js` 和 `source-view.js` 里的内联样式）
用户原话：“对整个系统的前端设计和 ui 设计出一套全新的方案，要求审美在线、重点清晰、排版合理、ui 有质感；并落地”

用户事先授权：本方案的所有取舍都由执行方自行拍板，不另行征询。每项拍板都写明理由和“如果错了要付出什么”，方便事后整体回退或局部调整。

## 1. 现状与问题

现在是一套深色“驾驶舱”主题：一份 600 行的 `style.css`，加 40 个 CSS 变量。问题有四个：

1. **底色太像。** 平台大部分页面是在读单据：评审表、预算表、交付明细、Excel 原表对照。深色背景上大段表格的可读性差，四层表面色只差 3% 到 5% 亮度，卡片和背景分不开，主次全靠字重撑。
2. **灯色被稀释。** 红黄绿是本平台唯一的判定信号，但品牌紫、信息蓝、数据五色都和它们同样鲜亮，重点不突出。
3. **商机和评审看不出层级。** 商机（实体，长期存在）和单次评审（事件）的页面长得一样，都是一张张平铺的卡片，看不出“我在商机档案里”还是“我在某一次评审里”。
4. **数字没有专门字体。** 金额、毛利率、人天和中文混用一套字体，数值不够醒目，也不像工程单据。

## 2. 设计方向（拍板）

**方向：“审图台”。** 浅色纸面主体，配墨蓝侧栏，借测绘制图的气质：

| 要素 | 取值 | 理由 |
|---|---|---|
| 主画布 | 暖白纸色 `#f3f1ec`，叠一层极淡的 24px 制图坐标网格 | 丰图是测绘公司，网格呼应图纸；纸面适合读单据，表格对比度高 |
| 卡片 | 近白纸张 `#fffefb`，1px 细线框，加一道很浅的投影 | 卡片像一张张单据压在台面上，层次靠明度差，不靠颜色 |
| 侧栏 | 墨蓝 `#152131` 深色，在侧栏内部局部改写文字变量 | 导航和工作区一深一浅，强对比，一眼分出“在哪”和“看什么” |
| 品牌色 | 钴蓝 `#2a4bb3`，只用于操作（主按钮、链接、焦点、选中） | 从紫色换成更冷、更像墨水的蓝，与红黄绿区分得开 |
| 判定色 | 红 `#c8323c`、琥珀 `#b9770e`、绿 `#16805f`，**只给灯色和状态用** | 颜色纪律：重点信号独占这三种颜色，装饰不得借用 |
| 数字字体 | `Bahnschrift`（Windows 自带的 DIN 体），后备 `DIN Alternate`、`Roboto Condensed` | 工程制图常用字体，金额和比率醒目且等宽；不需要下载，符合零依赖 |
| 正文字体 | `Microsoft YaHei UI`、`PingFang SC`、`HarmonyOS Sans SC` | 中文可读性优先，系统自带 |
| 等宽字体 | `Cascadia Mono`、`Consolas` | 用于单元格坐标、公式、商机码 |

**如果拍板错了**：只要把 `style.css` 和 `index.html` 恢复到 `8cdc1e7`，就能整体回到深色主题。所有改动都不碰业务逻辑。

**为什么不选另外两个方向**：

- **深色主题只调对比度**：改动最小，但用户要的是“全新的方案”。而且第 1 节的四个问题，有三个源自深色底本身。
- **引入组件库或设计框架**：违反零 npm 依赖铁律，排除。

## 3. 设计变量体系

保留全部旧变量名（`--surface-1`、`--text-3`、`--brand`、`--success-soft` 等），只换取值。原因是 `app.js` 的内联样式里有 170 多处直接写了 `var(--text-4)`、`var(--border-default)` 之类，换值就能整体翻新，不用逐处改。

新增的变量：

- 纸面系：`--paper`（卡片）、`--paper-2`（表头、次级面）、`--paper-3`（凹陷面）、`--rule`（细线）、`--rule-strong`、`--grid-line`（画布网格）
- 墨色系：`--ink`（侧栏底）、`--ink-2`
- 灯色系：`--light-red`、`--light-yellow`、`--light-green`、`--light-gray`，各自带 `-soft`（底色）和 `-ink`（同色系深字）
- 字体：`--font-num`、`--font-mono`
- 阴影：`--shadow-card`（纸张）、`--shadow-lift`（悬停抬起）
- 层级：`--hero-rule`（商机档案顶线）、`--event-rule`（评审事件左线）

文字四档：`--text-1 #1a2230`、`--text-2 #46505f`、`--text-3 #6b7482`、`--text-4 #8a919c`。在纸色上，四档都满足 WCAG AA 正文对比度（`--text-4` 只用于辅助说明，不低于 3:1）。

## 4. 版式与层级

### 4.1 全局骨架

- **侧栏**宽 224px，墨蓝底。
  - 分组标题用等宽小字，加大字距，像图签栏。
  - 选中项：左侧 3px 钴蓝竖条，加纸色半透明底，“从侧栏伸进工作区”。
- **内容区**最大宽 1440px，四周留白 24px，卡片间距 16px。
- **面包屑**改成“图签条”：返回按钮加路径，底部一道细线，和正文分开。

### 4.2 实体与事件分级（用户要求：实体概览与单次事件详情分级）

- **实体：商机 360，根节点 `#oppPage`。**
  - 第一张卡 `#oppProfileCard` 是“档案封面”：顶部 4px 墨蓝实线，标题 18px，带纸张投影，比其它卡片高一级。
  - 链路卡 `#oppChain` 紧随其后，作为“目录”。
  - 其余卡片保持标准层级。
- **事件：单次评审，根节点 `#reviewInstancePage`。**
  - 头卡 `#instHead` 用左侧 4px 钴蓝竖线，加一个“本次评审”的事件标记，表示这是从属于商机的一次流程。
  - 正文卡片缩一级，标题 14.5px。
- 两者在视觉上一眼可分：**封面是顶线，事件是左线。** 页面结构和交互不变。

### 4.3 重点信息

- **灯色横幅 `.light-banner`**：整条纸面，左侧 6px 灯色条，圆点带同色光晕，标题 16px。这是全站最重的视觉元素。
- **指标瓦片 `.stat`、`.metric-tile`**：数值用 `--font-num`，26 到 28px；标签用小号字，加大字距；悬停时纸张抬起。
- **毛利卡 `.margin-card`**：数值 36px，DIN 字体，钴蓝；告警态用琥珀。
- **表格**：
  - 表头用纸面次级底和 11.5px 加粗灰字，底部用 1.5px 墨线收束；
  - 行之间用细线；数字列用 DIN 字体，右对齐；
  - 悬停行用淡钴蓝底。

### 4.4 组件取值要点

- **按钮**
  - 主按钮：钴蓝实底，加一道内高光。
  - 次按钮：白纸底，配细线框。
  - 危险按钮：红底。
  - 高度：标准 36px，小号 30px。
- **状态标签 `.pill`**：淡底，配同色系深字和 1px 同色细框，看起来像印章。
- **表单**：输入框白底细框；聚焦时边框变钴蓝，外加 3px 淡钴蓝光圈。
- **页签 `.tabs`**：下划线式，选中项是 2px 钴蓝底线加深色字。
- **模态框**：纸面加大阴影，遮罩改成半透明墨色。
- **toast**：墨蓝底，白字，左边是状态色条。
- **时间线**：细墨线；圆点带纸色描边。

### 4.5 原表对照工作台 `.srcv`

- 改成浅色电子表格的观感，和用户在 Excel 里看到的一致：白格子、细灰网格线、表头和行号用纸面次级底。
- 状态取色：
  - 标签格：钴蓝细框；
  - 取值格：淡绿底；
  - 被剔除的格：琥珀斜纹；
  - 当前选中格：钴蓝底加 2px 钴蓝框。
- 一致、有差异、已换算三种状态沿用灯色系，深字配淡底。
- 布局不动。尤其要保留：窄屏（不超过 1100px）改成单列，390px 宽时页面没有横向溢出（SC-22 断言）。

## 5. 不变式（落地和验收都要守）

1. **选择器只增不减**：旧 `style.css` 里出现过的每个类名和 id 选择器，新文件里都要还在（用脚本比对类名清单）。DOM 结构、类名、id、`data-*` 属性一律不改。
2. **业务零改动**：判灯、算账、门禁、鉴权、接口一行不动。`app.js` 和 `source-view.js` 只允许改内联样式里写死的颜色值，把它们改成变量引用。
3. **零依赖**：不引入任何字体文件、框架或 npm 包。字体只用系统自带的。
4. **布局断言保持**：390px 宽时 `.srcv-grid` 是单列，且页面没有横向溢出。1024px 以下侧栏折叠成图标栏。
5. **“减少动效”偏好继续生效**：保留 `prefers-reduced-motion` 规则。

## 6. 落地步骤（G）

1. 重写 `style.css`：保留原来 21 个分节的顺序，选择器原样保留，只换取值；新增实体和事件分级、网格画布、数字字体等规则。
2. `index.html`：把 `color-scheme` 和 `theme-color` 改成浅色。
3. `app.js` 和 `source-view.js`：把为深色底写死的浅色字（`#eee`、`#ddd`、`#d8d9de`、`#f0f1f4`）和高亮灯色（`#3fc09c`、`#ef7b84`、`#e0a54a`、`#6ea6e8`、`#8b7fd4`、`#4a8`）换成对应变量，只改颜色值。
4. 自检：语法检查，选择器清单比对，对改动范围做 `git diff --stat`。

## 7. 验收（H）

- **截图**：用 playwright 真实浏览器逐页截图，存到 `review-platform/shots/UI_*.png`。覆盖这些页面：
  - 登录、工作台、商机列表、商机 360（PL00008572）、评审事件详情（含原表对照）；
  - 预算工作台、预算详情、交付明细、任务中心、研判看板、归档库、对话窗、系统设置；
  - 390px 窄屏下的原表对照。
- **零报错**：同时监听 `console.error` 和 `pageerror`，两者都必须是 0。
- **逐字段核对语义**，不只看页面不崩：
  - 商机 360 档案标题里的商机码，要和路由里的商机码一致；
  - 灯色汇总里红、黄、绿三个数，要和 `/api/opp/<code>` 返回值的计数一致；
  - 评审详情原表面板的标题，要和 `/api/reviews/<id>/source` 返回的文件名一致；
  - 灯色标签的文字只能是“红灯”“黄灯”“绿灯”之一（或该页面既有的灯色文案）。
- **视觉不变式**（用计算样式核对）：
  - 正文字色和卡片底色的对比度不低于 4.5；
  - 灯色横幅左侧色条的颜色等于对应灯色变量；
  - `#oppProfileCard` 有顶线，`#instHead` 有左线；
  - 主按钮背景色等于 `--brand`；
  - 数值元素的字体族里包含 `Bahnschrift`。
- **全量回归**：在 guard 保护下跑 `tests/run_all.js`，0 失败。
- **收尾**：只按显式路径提交，按既定配方同步到 GitHub。用 `final-launch.js` 重新拉起 8600 端口的在线服务，再跑 `online-check.js` 和浏览器重进核对。

## 8. 不做的事

- 不加暗色和亮色切换开关。只有一种主题，避免测试面翻倍。
- 不改任何页面的信息结构、字段顺序或文案。
- 不改移动端交互，只保证布局不溢出。
