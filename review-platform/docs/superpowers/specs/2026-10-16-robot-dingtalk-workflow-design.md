# 机器人与钉钉业务闭环设计

日期：2026-10-16

## 1. 目标

把现有预算、评审、前置任务能力收敛为一套机器人业务编排，同时把钉钉限制在可替换的输入输出边界。

1. 项目经理可通过机器人文字对话或 Excel 上传生成交付预算、项目预算，并在系统内人工确认。
2. 项目经理或销售经理可通过文字或 Excel 生成项目评审草稿；管理者可在后台针对新商机创建主动推送任务。
3. 评审提交后，系统按部门生成群消息，提醒配置角色进入系统完成前置任务。
4. 系统用户与钉钉员工、通知群之间有明确映射；未取得钉钉权限时可在本地完整预演，不产生外部调用。

## 2. 裁定

采用“本地机器人工作台 + 事务外发箱 + 可替换提供商适配器”。

不采用以下方案：

- 仅扩展现有 webhook：只能单向发通知，不能承接文字、文件、身份映射和可追踪投递。
- 直接写死钉钉实现：当前没有企业应用凭据、员工目录权限、文件下载权限和可靠回调条件，无法做真实验收，也会把业务流程绑死在外部接口上。

设计分两层：

- 业务层现在落地并可验收：对话、上传、草稿、人工确认、主动推送预览、部门任务消息、身份映射、外发箱。
- 钉钉适配层待权限获批后激活：员工同步、单聊/群消息发送、文件下载。适配器只翻译协议，不拥有预算、评审或任务状态机。

用户已授权采用推荐方案并无人值守推进，因此不再要求用户逐项选择；涉及真实外部发送、凭据写入或权限申请时仍停止在待激活状态。

## 3. 不变式

1. LLM 只做口语到白名单字段的翻译和缺项追问。
2. 判灯、算账、锁定、提交、结论确认继续由现有服务端规则与人工按钮完成。
3. Excel 继续走现有三个解析入口，不复制解析器。
4. 机器人不能代用户锁预算、提交评审、打灯、确认结论或归档。
5. 外部身份只映射到内部用户；权限始终由内部 `users.role`、`users.dept` 和现有端点裁决。
6. 未启用提供商时，所有主动推送只进入外发箱预览，不访问外网。
7. 通知失败不回滚业务事务；失败记录可见、可重试，但重试必须幂等。
8. 不修改判灯、财务计算、预算锁定和评审状态机。
9. 不新增 npm 运行时依赖，不修改 `config.json`。

## 4. 架构

### 4.1 机器人工作台

在现有 SPA 中增加统一工作台，复用现有能力：

- 商机上下文：选择或输入 `opp_code`，读取商机 360°。
- 交付预算：上传附 3，调用现有商机级交付导入端点；文字输入只补充交付行草稿，不自动确认。
- 项目预算：上传附 1，调用现有预算导入端点；文字输入复用 `skill=budget`。
- 项目评审：上传信息收集表，调用现有评审导入端点；文字输入复用 `skill=review`。
- 动作区只展示现有受权端点的按钮。确认交付、锁预算、提交评审仍由用户显式点击。

工作台是钉钉接入前的可验收入口，也是接入后的故障降级入口。

### 4.2 编排服务

新增一个小型业务模块 `robot-orchestrator.js`，只负责：

- 将标准化输入路由到现有预算、评审和交付入口；
- 生成缺项、下一步和人工确认动作描述；
- 为主动推送和部门任务生成标准消息；
- 写外发箱，不直接写业务状态。

文字生成交付预算使用独立的 `delivery` 抽取契约，只允许输出行数组中的 `content`、`stage`、`pm_pd`、`own_pd`、`rd_pd`、`prod_pd`、`travel_cost`、`note`。LLM 不得输出行成本、合计、预算状态或确认动作；行成本和合计继续由现有服务端单价与公式计算。该契约不能复用项目预算白名单冒充交付明细。

标准输入只包含：

```text
actor_user_id, channel, intent, opp_code, text, file_ref
```

标准输出只包含：

```text
reply, entity_refs, missing, actions, outbox_ids
```

`actions` 是前端可点击的现有 HTTP 动作，不允许编排服务直接执行状态迁移。

### 4.3 身份与目标映射

新增两张表：

- `robot_user_bindings`
  - `user_id`：内部用户，唯一真源；
  - `provider`：当前固定为 `dingtalk`；
  - `external_user_id`：获批后由员工目录同步；
  - `phone`：沿用通知 @ 手机号；
  - `status`：`unbound | active | disabled`；
  - `updated_at`、`updated_by`。
- `robot_targets`
  - `target_key`：如 `dept:财务BP`、`committee`、`sales_group`；
  - `provider`、`target_type`、`external_ref`；
  - `status`：`unbound | active | disabled`；
  - `updated_at`、`updated_by`。

未绑定行是有效配置状态，不是假数据。不得自动推断钉钉 userId 或群 ID。

### 4.4 事务外发箱

新增 `robot_outbox`：

- 业务引用：`opp_code`、`review_id`、`task_id`；
- 路由：`event`、`target_key`、`provider`；
- 内容：`payload_json`；
- 状态：`preview | ready | sending | sent | failed | cancelled`；
- 幂等：`idempotency_key` 唯一；
- 审计：`created_by`、`created_at`、`sent_at`、`attempts`、`last_error`。

规则：

- 未绑定目标或提供商未激活时写 `preview`。
- 目标已绑定且管理员显式启用后写 `ready`。
- 业务事务只负责入箱；发送器异步处理 `ready`。
- 同一评审轮次、任务和事件只生成一条外发记录。
- 现有 `notifySafe()` 在过渡期保留；新业务消息先入外发箱，不能双发。

### 4.5 提供商适配器

提供商接口固定为：

```text
resolveActor(externalIdentity)
sendDirect(target, message)
sendGroup(target, message)
fetchFile(fileRef)
health()
```

首期实现：

- `local` 适配器：不访问外网，把标准消息保存在外发箱并支持后台预览。
- `dingtalk` 适配器骨架：仅定义参数校验和未激活错误，不包含凭据，不发请求。

权限获批后只补充钉钉协议实现：员工目录查询、消息发送、文件下载。预算和评审代码不感知钉钉字段。

## 5. 业务流程

### 5.1 项目经理编制交付预算与项目预算

1. 用户进入机器人工作台并选择商机。
2. 文字输入走白名单字段合并；Excel 分别走附 3 和附 1 解析入口。
3. 工作台展示来源、缺项、预算试算和下一步。
4. 用户在现有页面确认交付预算。
5. 用户在现有页面锁定项目预算。
6. 机器人只提示结果，不代执行第 4、5 步。

### 5.2 项目经理或销售经理编制评审表

1. 用户选择已具备交付确认和锁定预算的商机。
2. 文字走 `skill=review`；Excel 走评审导入入口。
3. 生成评审草稿并关联同商机锁定预算。
4. 用户检查缺项、附件和来源后显式提交。
5. 提交门继续由现有服务端执行。

### 5.3 管理者主动推送新商机

1. 后台列出尚未具备评审草稿的待评审商机。
2. 管理者选择商机和接收人，生成一条 `review_invite` 外发记录。
3. 未接钉钉时状态为 `preview`，后台展示将发送的文字、接收对象和工作台深链。
4. 钉钉激活后，同一记录转为 `ready` 并由适配器发送；不得因重复点击生成重复邀请。

### 5.4 群机器人分发前置任务

1. 评审提交后，现有 `createTasks()` 产生部门任务。
2. 两个合法建任务入口都在 `createTasks()` 成功后调用同一个外发箱 helper，避免“新建时直接提交”和“草稿后提交”只有一条路径发消息。
3. 每个部门按“评审 id + 轮次 + 部门”汇总为一条 `task_dispatch` 外发记录。
4. 消息包含项目、灯态待办数、部门、任务深链和截止提示，不包含可直接改变状态的回调按钮。
5. 配置角色点击链接并登录系统，在现有任务页打灯或退回。
6. 任务端点继续核验登录用户部门，机器人不能代打。

## 6. API 与界面

新增管理接口：

- `GET /api/admin/robot/bindings`
- `PUT /api/admin/robot/bindings/:userId`
- `GET /api/admin/robot/targets`
- `PUT /api/admin/robot/targets/:targetKey`
- `GET /api/admin/robot/outbox`
- `POST /api/admin/robot/outbox/preview`
- `POST /api/admin/robot/outbox/:id/cancel`

新增用户接口：

- `GET /api/robot/workbench?opp_code=...`
- `POST /api/robot/invite-review`

工作台内部继续调用现有导入、对话和状态迁移端点，不新增第二套预算或评审写接口。

管理后台在现有 `#/admin/robot` 增加三个页签：员工绑定、群目标、外发箱。默认显示“本地预演，未连接钉钉”，不得伪装已接通。

## 7. 权限与安全

- 管理接口只允许 `admin`。
- 工作台沿用现有登录身份；主动邀请允许销售支持组和管理员。
- 绑定只接受已有内部 `user_id`，外部 ID 不授予内部权限。
- 外发内容统一转义，深链由现有 `PUBLIC_BASE_URL` 入口生成。
- 外发箱不保存文件正文、LLM 密钥、机器人 secret 或登录 token。
- 提供商配置继续由机器人管理中心保存并掩码读取；不进入 `config.json`。
- 真实发送开关默认为关闭，启用属于影响外部系统的管理操作。

## 8. 失败与降级

- LLM 失败：HTTP 200，保留草稿，转为表单补齐。
- Excel 解析失败：返回明确 4xx/5xx，不生成伪草稿。
- 身份或群未绑定：写 `preview`，指出缺哪个映射。
- 发送失败：记录 `failed` 和截断错误，业务状态不回滚。
- 重复事件：命中幂等键并返回既有外发记录。
- 钉钉不可用：用户仍可从本地工作台和任务页完成全部业务。

## 9. 测试与验收

永久测试至少覆盖：

1. 未启用提供商时不产生任何外部请求。
2. 员工绑定和群目标只能由管理员维护，且不改变内部角色权限。
3. 同一主动邀请、同一评审轮次部门任务不重复入箱。
4. 项目经理通过文字和 Excel 得到草稿，但口头“确认”不能锁定或提交。
5. 项目经理与销售经理可生成评审草稿，其他部门不能越权创建邀请。
6. 前置任务消息按部门汇总，链接指向真实任务页。
7. 外发失败不影响评审提交和任务完成。
8. 管理后台明确显示本地预演、未绑定和失败状态。
9. 浏览器层验证工作台上传/对话/人工确认路径，console 和 pageerror 为零。
10. 既有预算、评审、判灯、锁定、通知和全量门全部通过。

## 10. 实施边界

本轮完成：

- 本地工作台；
- 身份与目标映射；
- 外发箱与本地适配器；
- 主动邀请预览；
- 前置任务群消息预览；
- 管理后台与永久测试；
- 钉钉适配器接口和未激活状态。

等待外部条件后完成：

- 企业应用凭据配置；
- 员工目录真实同步；
- 钉钉单聊/群消息真实发送；
- 钉钉文件下载。

后四项需要用户完成权限申请和提供非公开配置，当前不得模拟成功或擅自调用外部钉钉。
