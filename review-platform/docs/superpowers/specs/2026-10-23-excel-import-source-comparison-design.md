**性质**：单个连续任务，内部分组只表示依赖顺序，不构成分批交付。
**上游诊断**：三条 Excel 通道、商机级与预算级交付存储、七份真实交付原件和六份现存预算/评审的只读核验；参考站「智能财报分析」只读学习。

## 1. 用户裁定与目标

> 交付预算导入进去后，预算为空的部分，行应该直接不存在；还有如果是Excel导入的，请做左右分区的对比，在原表里什么样，这里什么样；项目预算导入，也要这样！！！解析好的要跟原始的源做个对比；还有项目评审表也一样。

用户指定参考站的「智能财报分析」板块，学习解析对比方式，不复制财报业务。用户授权「不要给我发确认，你需要自己选择最合适的方案」：本说明书和实施计划直接自审、执行，不设置重复确认关口。

交付目标：

1. 交付明细五个预算数值均无正数的行不进入解析结果、不保存到系统、不参与确认门禁；现存无数值行一并剔除。
2. 项目预算、项目评审、两种挂靠方式的交付预算都有持久原件记录及左右对照，离开导入页面再返回仍可查看。
3. 左边是系统字段/明细，右边是原表；点击双方都能定位关联格，显示坐标与完整值。
4. 区分原表值、当次导入值、当前值，不将换算、未采用、在线补录及人工修改一律标成「一致」。
5. 为六份既有预算、六份既有评审、七份交付预算补原件对照，不伪造当年的解析快照。
6. 完成专项、浏览器和全回归，提交本任务文件，同步 GitHub，留下隐藏运行的 8600 服务供用户验收。

## 4. 数据流

原件上传 → 保存到 `data/uploads/import/` 或 `delivery/` → Python 解析字段/行、来源格和原表 → 既有白名单与数值归一 → 保存实体及导入快照 → 显式原件对照端点 → 与当前实体值比较 → 左右联动展示。

实体详情 GET 只嵌入原件元信息；大尺寸工作表与比较结果由受实体权限控制的 `/source` 端点返回。原件内容仅保存在本地，前端展示一律转义。

## 5. 无预算数字行的统一口径

### 5.1 判据

新增 `delivery-rows.js` 导出 `DELIVERY_NUM_KEYS`、`hasBudgetNumbers`、`pruneEmptyRows`、`pruneStoredDelivery`。

五键：`pm_pd / own_pd / rd_pd / prod_pd / travel_cost`。按现有数值解析净化为有限非负数，至少一键 >0 才保留。文字、备注、0、空值、非数字、负数均不能单独保留一行；只有差旅的行仍保留。

Python 在按两位小数输出并净化后使用同一正数判据：仅实施有数值只生成实施，仅运维有数值只生成运维，两边都有则各一行，两边都没有则进入 `skipped_rows`。不得出现 rows 已过滤而 row_sources 没过滤的索引错位。

### 5.2 写入与存量

- `cleanDeliveryRows` 和 `cleanDeliveryDraft` 共享 hasBudgetNumbers。
- 两个交付 PUT 返回 `dropped`，为提交数组长度减最终保存行数。界面显示「已剔除 N 行」，空行提示「无预算数字，保存时不保留」。
- 全部被剔除的有效附3 导入返回 400：「原表 N 行建设内容均无预算数字，未生成明细行。可改用在线编辑手动建行。」无建设内容仍沿用模板错误提示。
- `pruneStoredDelivery` 对 opp_delivery、budget_delivery 幂等清理，仅数量变化才 UPDATE，不改变 updated_at。confirmed 且剔除后全空才改 draft，其他状态不改。
- 启动时在 migrateV40 后执行。保留既有 G2 无挂靠门文字和 `/delivery/apply` 业务动作。

## 6. 原件存证模型

新增表 `import_sources`，DDL 常量 `IMPORT_SOURCES_DDL` 定义于 `import-source.js`，由服务与补录工具复用。

| 列 | 含义 |
|---|---|
| id | 原件记录主键 |
| entity_type | review / budget / delivery_budget / delivery_opp |
| entity_key | 评审/预算 id 的字符串或商机代码 |
| file_name / file_path | 用户文件名；UPLOAD_DIR 内的相对路径 |
| sheet | 原表工作表名 |
| audit_json | sheet、sources、pairs、unpicked、warnings、row_sources、skipped_rows、total_row、meta；不重复存旧 grid |
| imported_json | 当次白名单归一后的 fields/form/rows |
| importer_id / importer_name / created_at | 导入者与时间 |
| backfilled | 旧单补录标记 |

索引 `(entity_type, entity_key, id)`。只 INSERT，不 DO UPDATE；最新一条为当前对照来源。重新上传产生新记录，不把旧原件盖掉。预算版本沿 parent_id 查最近可用原件，返回 inherited_from；与派生版本当前字段比较。

四种成功导入均写源：预算、评审（含 history）、预算交付、商机交付。预算交付有 opp_code 时按实际写入表记 delivery_opp，否则记 delivery_budget。history 原件附件使用相对路径。

## 7. 解析器增量契约

### 7.1 共用工作表形状

`sheet = {name,max_row,max_col,truncated,cells,merges}`：

- cells 为稀疏数组 `[r,c,d]` 或 `[r,c,d,v]`，r/c 0-based；d 为显示值，v 为必要时保留的原始值。
- 日期显示 YYYY-MM-DD，百分号格式按 Excel 显示为百分数，浮点去无意义尾零；每格显示值最多 2000 字。
- 最多 300 行，超过时 truncated=true；合并区域 `[r1,c1,r2,c2]` 均 0-based。
- 保留原有 grid/pairs/sources 返回契约，旧解析器实验室不受影响。持久模型只存新 sheet，不重复旧 grid。

### 7.2 表单解析

`parse_form_xlsx.py` 的来源新增 raw（原格实际值）、raw_d（原格显示值）、selected、raw_pos（实际采用值坐标）、lab_positions（实际采用标签坐标）；多格合计保留 val_positions/raws。lab_positions 来自已采用候选所属的真实标签，上下文合计记录参与行实际非空标签格，保留空值与零值贡献项的标签，不靠相邻格或数值相等猜测。未被 pick 采用的匹配格记录 `unpicked`，原因明确。del_other 的重复项收集全部参与位置。

不更改 val_pos 选格语义：PA-8572-E [25,0]/[25,3]、PA-8111-E [22,6]/[22,8]、售前 [10,6]/[10,8] 保持。

### 7.3 交付解析

增加 skipped_rows `{r,content,content_pos,reason:'无预算数字'}`、meta.rows_skipped、meta.total_row_r、total_row.ops_rd/ops_prod、新 sheet。rows 与 row_sources 严格等长同序；完整原表仍包含被剔除内容，不能因系统不留行而把原表删掉。

## 8. 三值比较

`import-source.js` 中纯函数 `formComparison` 与 `deliveryComparison`，无判灯、算预算或状态写入。

### 8.1 字段比较

R=原格值，P=当次导入值，S=当前系统值。状态优先级：

| 条件 | 状态 | 必须展示 |
|---|---|---|
| P 存在，S 与 P 不同或已清空 | 已修改 | 导入值 → 当前值 |
| 多格参与计算且 P 存在 | 表内计算 | 原位置集合 |
| R 与 P 同语义且 S 未变 | 一致 | 原值、系统值 |
| R/P 均存在，R 转换成 P | 已换算 | 小数×100、去单位、日期区间折算月数、关键字识别或格式归一等真实原因 |
| R/P 均存在且不同，不能证实 R 转换成 P | 有差异 | 原表值 → 导入值，不编造换算原因 |
| R 存在但 P 缺，S 有值 | 在线补录 | 原表未采用原因 |
| R 存在但 P 缺，S 也缺 | 未采用 | 白名单/枚举/未解析等原因 |
| R 缺而 P 有 | 表内计算 | 无单一原格 |
| R/P 都缺而 S 有 | 在线补录 | 当前值 |

只有字段标签映射范围内的键进入对照。评审用 FIELD_LABELS 并补 opp_name；预算标签对齐 BUDGET_GROUPS 并补 opp_code。按原表行排序，无位置行在底部。标签坐标优先取显式 lab_positions，空数组表示无已知标签；仅旧来源未带该属性时回退 lab_pos，不推断额外标签。行次取首个实际标签坐标的行号+1。值位置优先取全部 val_positions，单格优先 raw_pos，仅旧来源缺少 raw_pos 时回退 val_pos；位置显示保留原始 sheet 地址。

counts 分状态计数，warnings 独立展示未匹配原标签，不把未知原格误当成功。

### 8.2 交付比较

按 `(content,stage)` 的出现次序队列匹配导入/当前行，保留重复行，不使用 content 单键去重。状态：一致、已修改、已删除、在线补录、已剔除。五个预算键变化展示原→新并高亮；剔除行注明「原表有、系统未保留（无预算数字）」。原表行排序，同一行实施先于运维，在线新增在底部。

合计校验逐阶段逐键列出原件合计、解析行合计、当前系统合计；只做披露，不能自动纠正或替用户确认。8068 的 17.5/11.5 是明确的差异见证。

## 9. API 与权限

| GET 端点 | 权限 |
|---|---|
| `/api/reviews/:id/source` | 已登录用户，沿用评审详情读口径 |
| `/api/budget/:id/source` | owner/销售支持组/admin |
| `/api/budget/:id/delivery/source` | 同预算详情 canRead |
| `/api/opp/:code/delivery/source` | canWriteOpp：建档人/项目经理/销售支持组/admin |
| `/api/import-sources/:id/file` | 根据来源实体类型核其实体权限；继承预算源仅向可读该版本的用户开放 |

source 响应 `{source,sheet,comparison:{rows,counts,check?}}`；无来源返回 source:null。实体 GET 的 `import_source` 只有 id、file_name、sheet、created_at、importer_name、backfilled、可选 inherited_from。导入返回保留 audit 并增加 source。

下载只接受数据库路径，`path.resolve` 后必须在 `UPLOAD_DIR + path.sep` 内，拒绝目录穿越，缺文件返回 404。Content-Disposition 使用 RFC5987 UTF-8 文件名，剥离系统加的时间戳前缀。前端 fetch 携 Bearer 后 blob 下载，不把 token 塞 URL。

实体下载权限只覆盖新增 `/api/import-sources/:id/file`；既有 `/uploads` 保持登录鉴权，仍是可能的替代访问路径，不据此宣称全平台原件保密。关联预算的持有人可读预算交付对照，但 `delivery_opp` 原件下载仍按商机建档人/项目经理/销售支持组/admin 判权，不从预算持有人推导商机权限。

大数据不能嵌入 review GET：任务中心最多预取 50 份同缓存键详情。实体级 source 端点在现有 invalidateApiCache 正则范围内，写后不会沿用旧比较。

## 10. SRCV 左右组件

组件使用实例作用域 id `sv<instance>_<r>_<c>`，内存按实体键存数据，不复用全局选中格。

- 顶部：文件/工作表/时间/导入者，全部/仅差异，下载原件；补录来源明确提示「导入值按当前解析器重新解析原件得出」。
- 左边「系统里」：字段表为行次、字段、原表值、系统值、状态、位置；交付表为行次、建设内容、阶段、五数值、状态、原表行。
- 右边「原表里」：列字母/行号，隐藏全空行列，合并单元格按可见行列重算跨度；标签格/值格/剔除格不同样式。点击两边联动、高亮、滚动定位，公式栏显示地址和完整值。
- ≤1100px 上下堆叠；不删原表中的剔除行；加载错误只在组件内显示，不破实体详情。
- 原表值、名称、坐标属性等全部转义，不插入原始 HTML。

挂载：L2 材料页 `#instSrc`、预算详情、预算交付页、商机交付区 `#opdlvSrcv`、导入后的预算/评审核对/交付核对页。机器人源文件行增加「查看原表对照 →」深链。

保留原有下一步文案：「进入预算单核对/锁定」「进入草稿编辑(补齐后提交)」「确认无误, 进入明细编辑 →」「重新上传 / 返回编辑页」。实验室的 impRvGridHtml/impRvPickCells 不动。

**请求不变量**：review 的 source 请求在 renderDetail 进入详情时发出并存内存，四页签切换/轮次切换仅渲染已有数据，不能从 renderInstBody 或 renderInstTab 发网络请求。IA-33/34 的指定实体请求计数保持；IA-37/38 的切换期间所有 `/api/` 请求均为零。
