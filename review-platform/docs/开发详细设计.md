## 1. 总则

### 1.1 三条架构决策（全文档的设计前提）

1. **单机器人三技能**：一个"项目评审机器人"内含预算编制/评审表编制/灯态评估三个技能模式，而非三个机器人——入口唯一、B 单号上下文贯穿、维护成本最低。
2. **对话层加在旁边，不动底座**：judge() 研判、draft→reviewing→returned→judged→archived 状态机、events 留痕、spawn('curl') LLM 通道全部复用；唯一"动骨架"动作 = 财务引擎从前端迁服务端（对话跑服务端，算账必须在服务端）。
3. **LLM 边界铁律**：LLM 只做翻译（口语→结构化）和提问（缺项→问询）；判灯/算账/代确认（锁定·提交·结论均人点）永不出代码；LLM 失败自动降级点选问答，HTTP 仍 200。

### 1.2 文件拆分与模块契约

| 文件 | 职责 | 新增/改造 |
|---|---|---|
| `server.js` | 入口 + 路由 + judge + 状态机（现状 730 行） | 改造 |
| `finance.js` | 财务引擎（computeBudget 迁入 + settings 参数化） | 新增 |

### 2.3 数据可行性三发现（开发必须知道）

1. **uploads 假文件陷阱**：`data/uploads/` 现存"预算表.xlsx"是 16 字节测试占位符，**不是真预算表**——fixture 一律以 `tests/fixtures/` 与 `tests/realdata/` 为准。
2. **毛利率格式归一化**：真实表单毛利率是小数（0.1508 = 15.08%），系统口径是百分数（'5.52'）——判例导入/存量迁移/Agent 抽取三处都必须 `×100` 归一化（实测已验证：08068 归一化后 15.08 正确判绿）。
3. **两处规则偏差**（阶段 1 修正项 1.6/1.7 的输入）：分包占比≥70% 现状判 red，判例实证判黄灯 XO 上会；XO 直通路由现状缺失，判例 08068 实证存在。

function signReport(reviewId, ttlMinutes = 60*24*7) {
  const exp = Date.now() + ttlMinutes*60000;
  const sig = crypto.createHmac('sha256', SECRET).update(reviewId + '.' + exp).digest('hex').slice(0, 16);

### 4.3 finance.js 设计

**迁移六步（每步独立可回归）**：①逐字复制 app.js computeBudget → ②硬编码值改 settings 参数缺省回落 → ③rateFor 部门→单价（未识别返回 null 触发缺失提示）→ ④接线 POST /api/budget/preview → ⑤app.js 改调 preview → ⑥跑 F-12 锚定放行后才删前端本地函数。

**公式（与现状逐字一致，冻结口径）**：

```
income     = contract / vat_rate                      // 1.06
net        = income − sub_cost − sw_outsource − flex_labor
salesLabor = sales_labor 手填非空 ? num(sales_labor)
             : round(max(contract/10000 − sub_cost/10000, 0) × sales_labor_rate)
tax        = income × tax_rate                        // 0.01
salesCost  = salesLabor + sales_travel + sales_entertain + sales_marketing + tax
assessProfit = net − salesCost
incentive  = max(assessProfit, 0) × incentive_base × incentive_factor
delivery   = dev_pd×rateFor(dev_dept) + prod_pd×price_prod_outsource
             + rd_outsource + del_travel + pm_cost + del_other
contribution = net − salesCost − delivery − incentive
margin     = net > 0 ? contribution / net × 100 : 0
```

1. 只输出 JSON：{"fields":{…}}，不输出任何其他文字/解释/markdown。
2. 只允许字段（白名单）：contract, sub_cost, sw_outsource, flex_labor,
   dev_dept, dev_pd, prod_pd, rd_outsource, del_travel, pm_cost, del_other,
   sales_labor, sales_travel, sales_entertain, sales_marketing,
   incentive_factor, project_name, customer。
3. 单位：金额类字段均为元；用户说"240 万"则 contract=2400000。
   dev_pd/prod_pd 为人天。incentive_factor 为数字（默认 1.0）。
4. dev_dept 只能是：交付处/行业拓展部/公共服务部/行业售前部/企业产品研发部/
   数据产品部/智能地图部/公共组件部/研发外包/生产外包 之一。
5. 用户未提及的字段不输出。禁止：计算数值、给建议、判断灯态、修改未提及字段。

USER:
当前草稿：{JSON.stringify(draft)}
用户说：{message}
```

**白名单与类型校验（mergeDraft）**：

```js
const BUDGET_WHITELIST = {
  contract:'num', sub_cost:'num', sw_outsource:'num', flex_labor:'num',
  dev_dept:'enum:交付处|行业拓展部|公共服务部|行业售前部|企业产品研发部|数据产品部|智能地图部|公共组件部|研发外包|生产外包',
  dev_pd:'num', prod_pd:'num', rd_outsource:'num', del_travel:'num',
  pm_cost:'num', del_other:'num', sales_labor:'num', sales_travel:'num',
  sales_entertain:'num', sales_marketing:'num', incentive_factor:'num',
  project_name:'str', customer:'str'
};
// 逐 key 校验：num 解析失败丢弃该字段（不 throw）；enum 不在枚举内丢弃；
// 白名单外 key 一律丢弃（LLM 无法注入 status/budget_id 等结构字段）
```

**必填缺失清单**：`MISSING_BUDGET = ['contract','sub_cost','dev_dept','dev_pd','del_travel']`（0 允许但必须明确出现——"无则填 0"由追问话术引导）；missing 为空才允许 lock（400 列出全部缺失项）。

**LLM 调用**：复用 spawn('curl') 通道（防火墙已验证）；deepseek-chat；temperature=0；max_tokens=500；超时 30s 失败不重试直接降级；返回剥 ```json 围栏 → JSON.parse → 校验 fields 为对象，否则 throw 降级。

**回复模板（buildReply，纯代码）**：

```
reply = [变更摘要：本轮更新字段=值列表（无变更则"未识别到新字段"）]
      + [精算行：净收入 X 万 / 交付成本 X 万 / 销售成本 X 万 / 激励 X 万 → 贡毛 X 万，毛利率 X%（<10% 追加"⚠ 黄灯水位"）]
      + [缺失行：还缺 N 项：中文标签列表（degraded 时改"请点选补齐"）]
      + [动作行：缺项清零时追加"确认锁定 vN？"]
actions = 缺项清零 && status=draft ? [confirm_lock] : []
```

**一轮对话时序**：

```
POST /api/agent/chat
 → auth → load budget（404/403）
 → agent_messages 写 user 原文
 → buildBudgetPrompt → extractFields（LLM 30s 超时）
     └ 失败 → degraded=true，跳过 merge
 → mergeDraft（白名单+类型过滤）
 → budgets.fields 落库（draft）
 → finance.computeBudget(fields, getSettings())
 → missing 校验
 → buildReply → agent_messages 写 assistant
 → 响应 { reply, draft, calc, missing, actions, degraded }   // LLM 失败仍 200
```

### 4.6 前端 #/agent 组件树

```
#/agent
