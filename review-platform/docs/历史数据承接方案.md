# 历史项目评审数据承接方案（V1.0 · 2026-10-10）

## 一、问题定义（摸底实证）

| 事实 | 实测证据 |
|---|---|
| 灯态/前置评审是今年才上线 | 现有库 480 张归档单 100% 产生于 2026（archived_at 年分布只有 2026），全部有 light/judge_detail/前置任务 |
| 历史评审不在系统里 | 2026 之前的项目评审只存在于线下 Excel（如 realdata 三份表所代表的存量模式），无灯态、无前置评审过程、只有人工结论（通过/不通过/放弃） |
| 系统三层都假设"在线流程" | 判灯引擎（judge）要求 form 字段齐全；门禁链（预算关联→提交→前置任务→研判→归档）不可跳过；归档 BI 的 light/greenRate 维度对无灯单无处安放 |

**目标态一句话**：历史评审数据（结果 + 关键字段 + 人工结论 + 来源 Excel 原件）完整进入系统——在归档库可检索、在 BI 可统计、在详情页可回看，且**与在线流程产生的数据泾渭分明、永不混淆口径**。

## 二、四要素

- **谁在做**：销售支持组（历史数据管理员角色）——批量补录公司历年项目评审
- **做什么**：把历史评审 Excel（老模板，无前置评审 sheet）批量上传 → 系统解析关键结果字段 → 以「历史单」形态直接落归档库
- **系统解决什么问题**：消灭"线上数据只有今年、领导看 BI 时历史为空"的断层——完整的项目评审资产库（历史 + 在线统一检索，口径分列）
- **产出什么东西**：历史导入通道（Excel 解析适配老模板 + 免流程直入归档）+ era 历史标记贯穿展示层 + BI 历史分档口径 + 本方案文档

## 三、设计方案（拍板默认，均可调）

### 3.1 数据模型：`era` 单据时代标记（核心）

reviews 表新增一列 `era TEXT DEFAULT 'online'`，取值两档：

| era | 含义 | 数据特征 |
|---|---|---|
| `online`（默认，存量 480 单自动归此档） | 系统在线流程产生 | 全字段：灯态/前置任务/事件流/预算关联 |
| `history` | 历史补录导入 | 无 light、无前置任务、judge_detail 记导入元数据、decision_result 存人工结论、附件存原件 |

**为什么用 era 而不是复用 status**：归档 BI/筛选/导出全部以 status='archived' 为主口径，历史单也落 archived——era 是横切正交维度，不破坏既有任何查询（DEFAULT 'online' 对存量零迁移）。

### 3.2 灯态处理：不补判，标"未评"（关键拍板）

历史单 **light 留空**（不是 NULL 语义歧义——存 'none'），理由：
- 用 2026 规则引擎给 2024 单判灯 = 穿越造假，业务不可接受（判定引擎的判例先例：期望值只能取自人工判定文书）
- 历史单的真实结论是**人工评审结论**（decision_result：通过/否决/放弃），这才是当年的事实
- BI greenRate 口径天然分列：`在线绿灯率`（191/480）与 `历史结论通过率`（新维度）——两根指标都真实

### 3.3 业务时间与导入时间分离

| 字段 | 历史单取值 | 用途 |
|---|---|---|
| `archived_at` | **历史评审发生日期**（Excel 中"评审日期/签批时间"，解析不出则用文件名年份兜底） | BI 周期维度、时间线业务时间轴 |
| events 首条 | "历史数据导入（来源文件名，导入人，导入时间）" | 审计留痕——分清业务发生时间与入库时间 |

### 3.4 导入通道：复用 Excel 导入 + `mode: 'history'`

`POST /api/reviews/import` 扩展参数（不新建端点，复用解析器与白名单）：

```
{ filename, data, type, mode: 'history', review_date: '2024-05-12' }  // mode 缺省=现行在线草稿导入
```

服务端差异行为（history 模式）：
1. 解析兜底：老模板无"信息收集与前置评审" sheet → 依次尝试 附1-预算表字段 / 第一张 sheet 键值对（标签→字段模糊匹配同现有解析器）
2. 免门禁：不走 BUDGET_REQUIRED_TYPES（预算关联是今年新规）、不走附件必填校验
3. 直入归档：`status='archived'`, `era='history'`, `light='none'`, `round=1`
4. 人工结论：解析"评审结论/审批意见"关键词 → decision_result；解析不到存"历史导入（结论未录入）"
5. 原件存证：来源 Excel 自动挂附件（field='历史评审表原件'）
6. 权限：仅 销售支持组/admin 可发起历史导入（普通销售不能补录历史）

### 3.5 展示层（三处贯穿）

| 位置 | 呈现 |
|---|---|
| 归档库列表 | 历史单加灰紫 pill「历史」；筛选器加时代开关（全部/在线/历史） |
| 详情页 | 时间线顶部一条说明卡：「历史单据 · 2024-05-12 评审 · 2026-10-10 导入 · 无前置评审过程（当年无此流程）· 灯态规则 2026 年启用」 |
| 归档 BI | light 分布四档（绿/黄/红/**历史未评**）；kpi 拆「在线绿灯率」与「历史结论通过率」两块 metric-tile；周期维度用业务时间（archived_at=历史日期）自动归位到 2024/2025 年份段 |

### 3.6 BI 端点适配（archive-stats 六处小改）

- light 聚合：`'none'` 档并入分布（前端第四色段）
- kpi：greenRate 分母改为 era='online'；新增 `historyTotal` + `historyPassRate`（decision_result 含"通过"）
- monthly：历史单按其业务时间落位（无需改——archived_at 已是历史日期）
- depts/amounts/types/routes：历史单天然参与（字段齐则算，缺字段进既有空档）
- 列表/导出：era 列显式输出

## 五、边界与回退

- **不做**：给历史单补判灯（规则穿越）、伪造前置评审过程（时间线只有导入事件一条，如实呈现"无过程"）
- **不做**：历史预算单导入（历史预算无锁定语义，预算先行是今年流程——历史单的金额走 form_json 字段直接参与 BI）
- 回退开关：era 列 DEFAULT 'online' 对未改造查询零影响；历史导入 mode 缺省不启用——灰度可控
- 数据红线：历史导入不写 tasks/judge 派生表，light='none' 与判灯引擎正交——判灯/算账/锁定/提交边界不动（LLM 边界铁律延续）

## 六、与既有资产的关系

- Excel 导入通道（本周交付）：解析器/白名单/异步 spawn 直接复用——本方案只是加了 history 分支
- 归档 BI（归档库BI产品方案.md）：八维度全部兼容，light 维度扩第四档
- 门禁三层落点：历史导入明确豁免（era='history' 时 BUDGET_REQUIRED_TYPES/附件校验不生效）——豁免点集中在 import 端点内，不松动在线流程任何门禁
