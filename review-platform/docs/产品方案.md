## 0. V3.0 的三个变化

1. **页面不再按"功能对象"组织，改按"业务办理顺序"组织**。旧导航（工作台/新建评审单/智能体/预算单/归档库/实验室/设置）回答的是"系统有哪些东西"；新导航五大模块回答的是"**一件事从商机到归档怎么办理**"。
2. **商机代码（opp_code）成为贯穿一切单据的业务主键**。交付预算、项目预算、评审单、前置评审、结论、归档全部以商机代码关联——"一个商机的全生命周期"一屏可见。
3. **系统管理补齐**：LLM 管理（已上线）、权限管理、机器人对接管理集中成一个模块，与业务模块分离。

## 1. 背景与问题

### 1.1 业务背景

公司对售前立项、投标决策、项目关键事项三类项目决策实行红黄绿灯评审制度：绿灯免上会直接推进、黄灯上会决策（部门级每周二 / XO 级每周五）、红灯打回且红线不可豁免。评审由销售支持组统筹，前置评审由六类部门 BP 打灯，量化指标由系统规则引擎判定。

### 1.2 现状痛点（Excel + 邮件流转的六个断点）

| 环节 | 现状问题 | 后果 |
|---|---|---|
| 算账 | 各自 Excel 各自公式，附1↔附3 跨表引用易断链；单价靠旧表和记忆 | 口径不一，财务调价无人同步 |
| 调价 | 改一处全表手动重算；报价版本靠文件名区分 | 谈判现场无轨迹无对比 |
| 提报 | 预算数字人工誊进 30+ 字段前置表 | 誊错一个数，判错一盏灯 |
| 判定 | 材料收齐后人工逐条对规则勾选 | 周期长、易漏判 |
| 上会 | 材料散落邮件，汇报质量看主述人发挥 | 会议决策质量不稳定 |
| 留证 | 结论靠邮件纪要 | 事后翻箱倒柜，审计口径各执一词 |

### 1.3 产品机会

把"填表"变成"说话"：用对话机器人承接全部录入，用确定性引擎承接全部计算与判定，用看板承接全部监控。**数据一次录入、全程自动流转**——Excel 退化为导入/导出格式，不再承担编制职能。

## 2. 产品定位与目标

### 2.1 定位

一句话：**按"商机 → 预算 → 评审 → 结论 → 归档"办理逻辑组织的项目评审平台，用三个对话技能承接录入，用规则引擎承接判定，以商机代码贯穿全流程**。

### 2.2 产品目标

| 目标 | 度量 |
|---|---|
| 录入零填表 | 预算与评审表 100% 可对话口述生成（表单页保留为确认与兜底） |
| 判定零人工 | 量化指标 100% 规则引擎自动，每灯附规则与数值、全程可解释 |
| 誊抄零发生 | 交付预算→项目预算→评审单逐级带数；精算数直达研判 |
| 结论全留痕 | 灯态、会议结论、事件流全量线上归档，可审计 |
| 商机全贯通 | 任一单据出发，一跳可达同一商机的其余全部单据与状态 |

### 2.3 不可退让的边界（产品红线）

- **判定权 100% 在规则引擎**：LLM 永不判灯、永不算账、永不代替人确认（锁定/提交/结论均由人点击）
- LLM 只做"翻译与提问"：口语 → 结构化字段、缺项 → 追问；产出停留草稿态，失败自动降级表单且流程不阻断
- 归档存系统判定的灯；结论单独存"是否同意"，两者独立
- POC 邮件审批不纳入系统；48h SLA 不做；CRM/PMS 对接后置

## 3. 核心设计决策

### 3.1 业务主键 = 商机代码（opp_code）

**为什么是商机**：评审业务的因果起点是商机（有商机才谈预算、有报价才谈评审、有评审才有结论）。预算单号 B-xxxx 只在"预算→评审单"两站有效；商机代码从第一站贯通到归档与数据分析。

**实体关系（文字版 ER）**：

```
商机代码 opp_code（业务主键，商机承接时生成/录入，唯一）
 ├─1—N 交付预算（附3 交付成本评估明细行，主挂靠键=opp_code）
 ├─1—N 项目预算单（B-xxxx-vN，版本链；汇总该商机交付明细）
 ├─1—N 项目评审单（售前/投标/关键事项，轮次）
 │        └─1—N 前置评审任务（按部门指标生成）
 │        └─1—1 综合研判（红黄绿灯 + XO 路由）
 │        └─1—1 上会结论（同意/不同意）
 └─1—1 归档快照（研判报告 + 全链事件留证）
```

**贯穿规则**：

| 编号 | 规则 |
|---|---|
| K1 | 数据库主键仍为自增 id（内部引用）；opp_code 是业务关联键，建唯一索引于"商机承接"层，单据层建普通索引 |
| K2 | 交付预算、项目预算、项目评审单创建时**必填** opp_code（从商机承接带入或现场录入一次、全程不再重复输入） |
| K3 | 任意列表/详情/BI 可按 opp_code 聚合筛选；单据互跳以 opp_code 为线索（评审单详情侧栏直达该商机的预算与交付预算） |
| K4 | 存量数据按"表单字段回填"策略迁移（reviews/budgets 已实现：从 form_json/fields 抽取 opp_code 幂等回填） |

**现状底座（2026-10-13 实测）**：reviews、budgets 两表 opp_code 列 + 索引 + 幂等回填已落地并有贯穿测试套件（OC-01~06 商机代码贯穿）；评审单列表已展示商机代码列。**缺口**：附3 交付明细仍挂 budget_id（见 3.2）；商机承接页与商机 360° 视图未建。

### 3.2 交付预算先于项目预算（挂靠键改造）

**业务因果**：先算清交付成本（附3 人天底稿）→ 再汇总整盘预算（附1 收入/税金/成本/贡毛）→ 再建评审单。现状是"先建预算单、再录附3"（budget_delivery.budget_id 挂靠），顺序反了。

**目标态**：交付预算以 **opp_code 为主挂靠键**，可先于项目预算独立编制（草稿态）；budget_id 降级为"已汇总到哪张预算单"的回填引用。项目预算创建/打开时自动按 opp_code 聚合该商机全部交付明细计入成本测算。

**迁移**：存量 budget_delivery 行按其所属预算单的 opp_code 回填主挂靠键，budget_id 保留不动（幂等，一次 ALTER+UPDATE）。

### 3.3 页面按办理流程组织（默认决策，可调）

| 用户提出的模块名 | 本文档定名 | 说明 |
|---|---|---|
| 评审信息收集 | **评审信息收集** | 保留原名；内部按"交付预算 → 项目预算 → 项目评审单"三步序 |
| 前置评审内容收集 | **前置评审打灯** | 收集的不是材料而是各部门的灯与意见 |
| 项目评审结论管理 | **评审结论管理** | 研判红黄绿灯 + 上会结论 |
| 归档管理和数据分析 | **归档与数据分析** | 归档库 BI（8 维已上线）+ 商机 360° |
| 系统管理 | **系统管理** | LLM / 权限 / 机器人对接 / 财务配置 / 解析器实验室 |

## 5. 业务办理主线（一屏流程图）

```
商机承接 → 交付预算 → 项目预算 → 项目评审单 → 前置评审打灯 → 综合研判 → 上会结论 → 归档 → 数据分析
(opp_code)  (附3底稿)   (B-xxxx-vN)  (三类型)      (六部门BP)     (红黄绿灯)   (同意/不同意)        (BI+360°)
    │           │           │             │              │             │            │           │
    └────────────────── 全程以 opp_code 贯穿，任一节点一跳可达全链 ──────────────────────────────┘
```

| 步骤 | 谁做 | 系统帮他解决什么 | 产出 |
|---|---|---|---|
| 商机承接 | 销售/项目经理 | 登记商机代码与客户，之后全程免重复输入 | 商机档案（opp_code） |
| 交付预算 | 项目经理（商务协作） | 人天底稿对话式录入、单价自动取财务配置、无需先建预算单 | 附3 成本明细（挂 opp_code） |
| 项目预算 | 项目经理 | 自动聚合该商机交付明细；口述即精算；调价生成新版本 | B-xxxx-vN（锁定后可评审） |
| 项目评审单 | 销售经理 | 引用预算单零誊抄建单；AI 抽取补充；提交前预判灯态 | 评审单（轮次） |
| 前置评审打灯 | 六类部门 BP | 任务 @到人、卡片内嵌判定标准原文、带意见退回 | 各部门灯 + 意见 |
| 综合研判 | 规则引擎 | 合并各灯、核验 11 项 XO 升级条件、确定会议级别、出报告 | 综合灯态 + 报告 |
| 上会结论 | 销售支持组（人工录入） | 结论录入、意见冲突自动升级 XO、通知送达 | 同意/不同意 |
| 归档 | 销售支持组 | 全链快照（灯/结论/事件/预算版本）固化不可篡改 | 归档档案 |
| 数据分析 | 支持组/管理层 | 8 维 BI + 按商机 360° 复盘 | 决策依据 |

## 6. 信息架构与页面设计

### 6.1 导航重组（现状 → 目标）

**现状（按功能对象）**：工作台 / 新建评审单 / 智能体 / 预算单 / 归档库 /（admin）解析器实验室 / LLM 设置。

**目标（按办理流程，一级菜单六个）**：

```
① 工作台          ——按角色聚合"我该干什么"（所有人）
② 评审信息收集     ——商机总览 | 交付预算 | 项目预算 | 评审单（销售/PM/支持组；智能体对话窗并入本组）
③ 前置评审打灯     ——我的前置任务 | 指标口径（六类 BP + FDE）
④ 评审结论管理     ——研判看板 | 上会结论 | 本周排会（支持组/admin）
⑤ 归档与数据分析   ——归档库 BI | 商机 360°（支持组/管理层）
⑥ 系统管理        ——LLM 管理 | 权限管理 | 机器人对接 | 财务配置中心 | 解析器实验室（admin/财务BP）
```

| 角色可见性 | ① | ② | ③ | ④ | ⑤ | ⑥ |
|---|---|---|---|---|---|---|
| 销售/项目经理 | ✓ | ✓(自己) | — | — | — | — |
| 部门 BP / FDE | ✓ | — | ✓(自己) | — | — | — |
| 销售支持组 | ✓ | ✓ | ✓ | ✓ | ✓ | — |
| 财务 BP | ✓ | ✓ | ✓ | — | — | ✓(财务配置) |
| admin | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

**现状映射**：工作台=现有 #/home；新建评审单+智能体+预算单归入②；归档库归入⑤；解析器实验室+LLM 设置归入⑥。**需新建**：商机总览、交付预算独立页、我的前置任务、研判看板/排会独立页、商机 360°、权限管理、机器人对接。

### 6.2 模块一 · 评审信息收集

**四要素**：谁在做=销售/项目经理（支持组可代查）；做什么=从商机到评审单的三级信息流；系统解决=数据一次录入逐级带数、消灭誊抄；产出=可提交评审的完整单据链。

**页面设计**（本模块内四页，顶部始终显示当前商机代码面包屑，可点回商机总览）：

| 页面 | 路由 | 结构与关键交互 |
|---|---|---|
| 商机总览 | `#/opps` | 商机列表（opp_code/客户/最新预算版本/评审单数/当前灯态/结论状态一屏聚合），按 opp_code 聚合现有数据；行点开=商机 360°。"+"承接新商机：录入 opp_code + 客户名即建档案 |
| 交付预算 | `#/delivery` | 附3 交付成本评估明细编制页：选商机（opp_code）→ 行式编辑（内容/实施·运维阶段/人天）→ 成本自动实算（单价取财务配置）；对话口述与 Excel 导入（附3 模板）三通道；**不再要求先建项目预算** |
| 项目预算 | `#/budgets` | 现预算单列表+编制，增强：创建时选商机自动聚合该商机交付明细；版本对比视图 |
| 项目评审单 | `#/reviews` | 现评审单列表+建单（表单/对话/Excel 导入三通道），保持 bid/presale 必须关联锁定预算单的门禁 |

**智能体对话窗**（现 `#/agent`）保留为②组内的辅助入口：技能①预算编制、技能②评审表编制、技能③预判，能力与规则不变（详见《开发详细设计》）。

**模块规则**：三步顺序软引导（交付预算未编时项目预算页给提示链；非强制——投标场景允许直接建预算）；建评审单仍强制预算锁定（B2-1 不变）；opp_code 全程自动带出不再重复输入（K2）。

### 6.3 模块二 · 前置评审打灯

**四要素**：谁在做=六类部门 BP + FDE；做什么=对本部门指标打灯填意见；系统解决=任务 @到人、判定标准原文内嵌、不用翻制度文件；产出=部门灯 + 意见（带意见退回直达申请人）。

| 页面 | 路由 | 结构与关键交互 |
|---|---|---|
| 我的前置任务 | `#/tasks` | BP 登录默认落地页：待打灯清单（单据/指标/标准/截止），行点开=打灯页；已完成/已逾期分组 |
| 打灯页 | 评审单详情内嵌 | 指标卡：判定标准原文（绿/黄/红三栏）+ 打灯选择 + 意见框；带意见退回=直达申请人并留痕 |

**数据 BP 指标升格（V3.0 新增）**：表单已有 data_plan（数据方案）/ data_content（数据内容）/ data_compliance（数据合规）/ data_review（数据审查）字段，升格为数据 BP 前置评审指标——从"躺在表单里"变成"数据 BP 打灯"，规则矩阵同步新增对应条目（红绿判据见《开发详细设计》新增节）。

### 6.4 模块三 · 评审结论管理

**四要素**：谁在做=销售支持组（结论录入）+ 评审委员会（决策）；做什么=盯研判、排会、录结论；系统解决=黄灯自动排会队列、风险卡片一键投屏、结论与灯分离存档；产出=会议决策留证。

| 页面 | 路由 | 结构与关键交互 |
|---|---|---|
| 研判看板 | `#/judge` | 全部在评单据的灯态漏斗（草稿/评审中/待上会/待结论/已归档）+ 逾期部门催办 + 研判报告直开 |
| 本周排会 | `#/meetings` | 周二部门级/周五 XO 级队列，主述人+风险卡片链接（投屏用） |
| 上会结论 | 评审单详情内嵌 | 现有 /decision 能力：同意/不同意+说明；"意见不一致"勾选自动升 XO；红灯打回重提进新轮次 |

三色分发规则不变：绿=钉钉委员会群发布+归档；黄=排会+周一汇总推卡片；红=打回申请人（红线不可豁免）。

### 6.5 模块四 · 归档与数据分析
