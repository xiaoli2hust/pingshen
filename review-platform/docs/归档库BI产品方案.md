# 归档库 BI 分析视图 · 产品方案

| 项 | 内容 |
|---|---|
| 版本 | V1.0（2026-10-09） |
| 背景 | 归档库现有形态为平面表格（项目/类型/申请人/灯态/路由/归档时间），378 单归档存量沉睡——用户需要从历史数据中直接读出结论："哪类项目最容易黄、哪个部门最爱亮黄、多少钱的单在上会" |
| 数据基线 | 2026-10-09 摸底实测：378 单（bid 330 / presale 24 / change 24；黄 224 / 红 17 / 绿 137；金额 354 单含值；风险项 20 类；结论录入 49；路由 XO 151 / 免上会 137 / 部门级 73） |

## 一、四要素

- **谁在做**：销售支持组（看全量复盘）、管理层（看趋势与分布）、申请人（看自己的单子落在哪个区间）
- **做什么**：打开归档库，顶部即见 BI 分析区，一眼读出历史评审的结构性结论，再下滑看明细列表
- **系统帮他解决什么问题**：把"378 行表格靠肉眼翻"变成"8 个维度 10 秒读完"——风险项排行直接告诉流程管理者哪些指标是常客（当前实测：贡献毛利 89 次、指定供应商 50 次、签约转包 36 次），部门命中率告诉谁最爱亮黄（财务 BP 38 黄），金额分布告诉多少钱的单在走评审
- **产出什么东西**：归档库页 BI 分析区（4 KPI 卡 + 8 维度图）+ 1 个聚合数据接口；后续阶段 4 看板可复用同一接口

## 二、八个数据维度

| # | 维度 | 展示形态 | 口径 |
|---|---|---|---|
| 1 | 归档总数 / 绿灯率 / 平均轮次 / 结论录入率 | 4 张 KPI 大数字卡 | status='archived' 全量；绿灯率=green/total；平均轮次=avg(round)；结论录入率=decision_result 非空占比 |
| 2 | 灯色分布 | 红/黄/绿三段占比条 + 图例 | reviews.light 计数 |
| 3 | 评审类型占比 | 三类横条 | presale/bid/change 计数 |
| 4 | 月度归档趋势 | 按月柱状（近 12 个月，缺月补零） | archived_at 月份分组 |
| 5 | Top 10 风险项排行 | 横向条形降序 | judge_detail 中 level != green 的 name 聚合计数（BI 核心洞察） |
| 6 | 部门黄/红命中率 | 六部门横条（黄+红次数，按占比排序） | tasks（归档单）按 dept × light(yellow/red) 计数 |
| 7 | 金额分布 | 四档区间（<50 / 50~100 / 100~500 / ≥500 万）柱状 + 总额 | form_json.contract_amount 解析（万） |
| 8 | 评审路径分布 | XO / 部门级 / 免上会三段占比条 | route 文本匹配 |

**周期维度（建单→归档天数）暂不展示**：当前存量全部为测试脚本秒级流转（周期全 0），展示无意义；数据结构已支持，真实使用出值后随阶段 4 看板启用，不造假数据。

## 三、权限口径

与归档列表一致：**登录全员可见**（归档单本身全员只读，BI 聚合不含未归档单/草稿/在途单——只聚合 status='archived'，无越权面）。

## 四、用户验收标准（BI-01~12 用例表）

| 用例 | 验收 | 放行 |
|---|---|---|
| BI-01~08 | 八维度数字与 SQLite 直查逐项一致（断言源=探针 SQL 复刻，禁止手拍） | 全过 |
| BI-09 | 空态兜底：无归档数据时各维度 0/[]，页面不崩 | 过 |
| BI-10 对抗 | 接口对非法 query 参数（?scope=xxx 等）容错忽略，不注入不 500 | 过 |
| BI-11 对抗 | BI 只含归档单数据（在途/草稿单数字不泄露进聚合） | 过 |
| BI-12 | 聚合性能：378 单 < 300ms | 过 |
| 浏览器层 | 归档页 BI 区组件渲染 + 全程无 JS 报错 + 截图 | 过 |
| 回归 | 既有 10 套 run_all + 3 个 H 脚本零破坏 | 全绿 |

## 五、约束

- 零依赖延续：全部纯 CSS（分布条/排行条形/柱状）实现，不引图表库
- 不动既有 id/按钮文本/hash 路由（H 脚本兼容红线）
- 展示零依赖真实数据，维度当前为 0 的（周期）不展示不造假
