系统价值总账——为什么不能停在"Excel 编预算 + 系统收表"
核心主张：数据一次录入、全程自动流转。预算在系统里算（口径唯一）→ 评审一键引用（零誊抄）→ 研判用精算数字（零读表误差）→ 报告自动生成 → 结论线上留痕。Excel 退化为导入/导出格式，不再承担"编制"职能——否则系统只是个收发室。
环节现在（Excel + 邮件流转）上系统后谁直接受益
算账各自 Excel 各自公式，附1↔附3 跨表引用易断链；单价靠旧表和记忆，财务调价无人同步财务配置中心唯一口径；预算页只填"量"不碰"率"；财务改价全平台即时生效项目经理 / 财务
调价改一处全表手动重算易错；报价版本靠文件名区分，无轨迹无对比报价沙盘改一项全表联动重算；每版自动快照、多版并排对比销售经理（谈判现场）
提报预算数字人工誊进 30+ 字段前置表——誊错一个数，判错一盏灯口述/一句话引用预算单，AI 抽取生成表单 + 多轮补缺，零誊抄零填表销售经理 / 支持组
判定材料收齐后人工逐条对规则勾选；靠 LLM 读 Excel 依赖映射、会读错结构化数据直接进规则引擎，秒级出灯；每盏灯附触发规则与当前值支持组 / 评审委员会
上会材料散落各邮件；汇报质量看主述人临场发挥风险卡片（周一/周四钉钉推送）+ 投屏报告（汇报论据提示内嵌）评审委员会
留证结论靠邮件纪要，事后翻箱倒柜、口径各执一词结论线上录入、报告固化、事件全史可溯，归档即审计材料全员（复盘/审计）

机器人架构总图（一个入口 · 三个技能 · 确定性底座）
申请人与"项目评审机器人"对话完成全部录入——把"填表"变成"说话"。灯态判定、财务计算、流程流转 100% 由确定性代码执行，LLM 只做"翻译与提问"；任一环节 LLM 失败 → 自动降级网页表单，流程不阻断。POC 邮件审批不纳入本系统。

锁定预算单 B-xxxx-vN 是唯一衔接凭证：技能②引用它带入合同/贡毛率/分包占比；技能③研判时精算数优先于表单粗填值；归档时预算版本快照随档案固化。一个预算单可关联多张评审单（谈判多轮报价→分别提报）。变更（R6）也回技能①出变更版。

技能① 预算编制（多轮问询）

项目经理：交付处，10 个人月，差旅 2 万

R1 · 成本测算（技能① 预算编制机器人——先算账、再报价，远早于提报评审）
业务顺序：商机出现 → 与机器人对话编制预算（可能持续数周、随谈判反复调整）→ 锁定版本作为报价依据。预算单为独立实体（B 编号/版本/状态），不依附评审单；本阶段零打扰部门。对话失败可随时切网页表单继续，数据同源。
