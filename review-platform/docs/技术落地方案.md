## 1. 总原则

机器人不是重写系统，是在现有骨架上加**对话层**。三技能的地基（财务引擎、规则引擎、状态机）都已在代码里，唯一一次"动骨架"是把财务计算从前端迁到后端（对话跑在服务端，算账必须在服务端）。

三条铁律：
1. **底座原样复用**：judge() 研判、draft→reviewing→returned→judged→archived 状态机、events 留痕、spawn('curl') LLM 通道全部不动
2. **对话层加在旁边**：新增 Agent 端点 + 会话表，与现有表单页并存互通（同一预算单，网页和对话两个入口都能操作）
3. **机器人回复主体是代码模板**：回复里的数字、缺失清单、确认请求由代码生成；LLM 只做输入侧字段抽取——LLM 挂了就降级为引导式问答，流程不断

## 3. 目标架构（四层）

```
入口层     钉钉机器人（Stream 长连接，二期） ｜ 网页对话窗（一期） ｜ 看板页
           └──────── 入口适配：同一 Agent 核心两个壳 ────────┘
Agent 层   /api/agent/chat 对话循环：LLM 抽取(草稿态) → 代码 merge → 财务精算
           → 缺项校验 → 代码模板回复（数字+问询+确认请求）→ 人点确认生效
确定性底座 财务引擎(服务端) ｜ 规则引擎 judge ｜ 状态机 ｜ 通知适配器(钉钉/邮件)
数据层     budgets(版本化) ｜ reviews(+budget_id/+decision) ｜ tasks ｜ events
           ｜ agent_messages ｜ settings(财务配置) ｜ users/sessions/attachments
```

LLM 边界（工程保障，详见 §7）：LLM 每轮只返回 `{"fields":{增量}}`，经字段白名单过滤 + 类型校验后合并进草稿；计算、判灯、状态流转、通知发送全部是确定性代码。

## 4. 数据库设计

新增三表 + 旧表加列（全部走 `CREATE TABLE IF NOT EXISTS` / `ALTER TABLE ADD COLUMN` 幂等演进，与现有模式一致）：

```sql
-- 预算单（独立实体，版本链）
CREATE TABLE IF NOT EXISTS budgets (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  code TEXT NOT NULL,                       -- 'B-2026-0001'（年份+序号）
  version INTEGER NOT NULL DEFAULT 1,
  status TEXT NOT NULL DEFAULT 'draft',     -- draft | locked
  owner_id INTEGER NOT NULL,                -- 项目经理
  project_name TEXT DEFAULT '',
  fields TEXT NOT NULL DEFAULT '{}',        -- 草稿字段 JSON（合同/分包/人天/部门/差旅…）
  calc TEXT,                                -- 锁定时精算快照 JSON
  settings_snapshot TEXT,                   -- 锁定时财务配置快照 JSON（不追溯）
  parent_id INTEGER,                        -- 上一版本 budgets.id（版本链）
  created_at TEXT, updated_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_budgets_code ON budgets(code);

-- 对话留痕（审计 + 回放调提示词）
CREATE TABLE IF NOT EXISTS agent_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  budget_id INTEGER,                        -- 技能①②上下文二选一
  review_id INTEGER,
  role TEXT NOT NULL,                       -- user | assistant
  content TEXT NOT NULL,                    -- 原文/模板回复全文
  created_at TEXT
);

-- 财务配置中心（财务 BP 定期更新）
CREATE TABLE IF NOT EXISTS settings (
  key TEXT PRIMARY KEY,                     -- 如 'rate_regular_delivery'=1696
  value TEXT NOT NULL,
  updated_at TEXT, updated_by TEXT
);

-- 旧表演进
ALTER TABLE reviews ADD COLUMN budget_id INTEGER;      -- 一键关联预算单
ALTER TABLE reviews ADD COLUMN decision_result TEXT;  -- '同意' | '不同意'
ALTER TABLE reviews ADD COLUMN decision_note TEXT;
ALTER TABLE reviews ADD COLUMN decision_by TEXT;
ALTER TABLE reviews ADD COLUMN decision_at TEXT;
```

**预算字段 JSON 契约**（budgets.fields，与现有预算页签字段同源）：

}

## 5. 后端详细设计

### 5.1 财务引擎迁移（批次 2 第一步，放行门槛最高）

- 从 app.js 提取 computeBudget 到 server 端 `finance.js`（CommonJS require，仍是零依赖），**公式逐字一致**：

```
income     = contract / 1.06
net        = income − sub_cost − sw_outsource − flex_labor
salesLabor = sales_labor 手填 ‖ round(max(contractWan − subWan, 0) × 1727)
tax        = income × 0.01
salesCost  = salesLabor + sales_travel + sales_entertain + sales_marketing + tax
assessProfit = net − salesCost
incentive  = max(assessProfit, 0) × 0.077 × incentive_factor   （系数配置化后接入）
delivery   = dev_pd × rate(dev_dept) + prod_pd × 320 + rd_outsource + del_travel + pm_cost + del_other
contribution = net − salesCost − delivery − incentive
margin     = net > 0 ? contribution / net × 100 : 0
```

- 单价/税率/系数改读 settings（缺省回落到上表默认值——即当前硬编码值）
- 新端点 `POST /api/budget/preview`：入参 fields JSON → 返回 calc JSON；前端预算页签改调此接口（**前后端单一真相源**：对话和表单用同一个计算器）
- **放行门槛**：PL00008572 锚定复算六组数字迁移前后逐项一致——收入 226415.09 / 销售人力 41448 / 税金 2264.15 / 激励 13298.13 / 贡毛 12508.82 / 毛利率 5.52%；写进 test_agent_budget.js 永久回归

### 5.2 Agent 对话循环（核心新增）

**接口契约**：

```
POST /api/agent/chat
{ "budget_id": 12, "message": "把分包改成 80 万" }

→ 200 {
  "reply": "已更新：分包 80 万。当前：净收入 146.4 万 / 贡毛 68.2 万 / 毛利率 46.6%。还缺 0 项。",
  "draft":   { …合并后 fields },
  "calc":    { …财务引擎输出 },
  "missing": [ "delivery_dept" ],
  "actions": [ { "type": "confirm_lock", "label": "确认锁定 v2" } ]
}
```

**循环状态机**（每轮请求内完成，无长事务）：

```
用户消息 ──→ ① LLM 抽取（单次调用，结构化输出）
              system: 你是字段抽取器。只输出 JSON {"fields":{…}}，
                      只允许白名单字段，禁止计算/建议/判灯。
              user:   当前草稿 JSON + 用户消息原文
         ──→ ② 字段白名单过滤 + 类型/范围校验（数字字段 NaN 拒绝）
         ──→ ③ merge 进草稿（budgets.fields，draft 状态）
         ──→ ④ 财务引擎精算（服务端 finance）
         ──→ ⑤ missingFields(fields) 缺项校验（纯函数，清单驱动）
         ──→ ⑥ 代码模板组装回复：变更摘要 + 精算数字 + 缺项问询 + 可执行动作
         ──→ ⑦ agent_messages 双向留痕
```

**降级路径**（LLM 失败 / 超时 / 返回非法 JSON）：跳过①②，直接⑤⑥——回复"未能理解，请点选补齐"并附缺项清单，前端渲染为点选项。算账、锁定、提交能力不受影响。

**确认门**：`confirm_lock` 动作不是对话消息，是独立端点 `POST /api/budget/:id/lock`（人点击触发）；LLM 无法通过对话触发锁定。

### 5.3 预算单 API

| 端点 | 语义 |
|---|---|
| POST /api/budget | 建草稿（生成 code B-2026-XXXX） |
| GET /api/budget/:id | 取预算单（含 calc） |
| PUT /api/budget/:id | 更新草稿 fields（表单通道） |
| POST /api/budget/:id/lock | 确认锁定：固化 calc + settings_snapshot，status=locked |
| POST /api/budget/:id/newversion | 基于锁定版生成 v(N+1) 草稿（parent_id 链） |
| GET /api/budget/:id/versions | 版本列表（并排对比数据源） |
| POST /api/budget/preview | 精算预览（不落库） |
| POST /api/budget/import | 存量 Excel 迁移（复用 L1 映射，未匹配项返回人工确认清单） |
| GET /api/budget/:id/export | 导出复刻官方 Excel 模板（打印/签字） |

权限：owner 与协作人可编辑草稿；锁定后所有写接口拒绝。

### 5.4 评审表关联与研判接线（批次 3）

- 提交校验：`reviews.budget_id` 必须指向 status=locked 的单，否则 400 并返回指引文案
- 研判取数：judge() 读到关联预算时，贡毛率/分包占比**优先用 budgets.calc 精算值**（表单粗填值仅兜底）
- 技能②对话循环复用 §5.2，上下文换 review_id + bid 表单字段集（FIELDS 已有 34 字段），首条消息解析"用 B-xxxx 建评审单"→自动带入并开始缺项追问
- 预判灯态：dry-run 调 judge() 不落 status，结果随 preview 返回

### 5.5 结论 API

`POST /api/review/:id/decision`（仅销售支持组/admin）：写 decision_result/note/by/at + addEvent + 触发通知；勾选 `opinion_conflict` → 重跑路由（XO 升级）。

### 5.6 通知适配器与定时（批次 3）

- 钉钉 webhook：`notify(userPhones, markdownCard)` 内部走 spawn('curl')（与 LLM 同通道，公司防火墙兼容已验证）；users 表加 dingtalk_userid/phone 列
- 绿灯发布：研判为绿 → 机器人文案推委员会群（对应规则原文"邮件输出智能体评审结论并留档"）
- 周一汇总 / 周四加推：进程内 `setInterval` 对表驱动（服务常驻即可，无需系统级定时器）
- 邮件通道：后置项，接口预留 `notifyEmail()` 适配位（SMTP 用 Node 原生 net/tls 可实现，零依赖不破坏）

### 5.7 看板聚合（批次 4）

`GET /api/stats?scope=funnel|light|amount|cycle|mine`：SQL 聚合 reviews/tasks/budgets，按角色过滤（支持组全量、管理层全量脱敏、申请人只看自己）。前端 #/dashboard 渲染。

## 7. LLM 工程边界（保障清单）

| 机制 | 实现 |
|---|---|
| 结构化输出 | 提示词强制 `{"fields":{…}}`；返回非法 JSON 直接降级 |
| 字段白名单 | 合并前过滤，LLM 无法注入未知字段/改状态字段 |
| 类型校验 | 数字字段 NaN/负数拒绝（金额、人天） |
| 人确认门 | 锁定/提交/结论是独立端点人点击触发，对话不可触发 |
| 留痕回放 | agent_messages 全量存，提示词迭代可拿真实对话回归 |
| 失败降级 | 降级引导问答；流程核心（算账/研判/归档）不依赖 LLM |
| 永久禁区 | LLM 判灯、算账、代确认、自动归档、无人值守调用 |

模型分工：DeepSeek Flash（deepseek-chat）承担对话抽取（已实测可用）；Pro（deepseek-reasoner）留 L3 文字辅助（未实测，后置）。

## 8. 安全设计

- 报告/风险卡片链接：HMAC 签名 token + 过期时间，免登录只读（批次 1 落地）
- 密钥：仅 config.json 服务端，不进前端、不外发；config 不入 git
- 权限：归档/重判/结论录入仅销售支持组与 admin（沿用现有 role 校验模式）
- 附件 ≤10MB 沿用

|---|---|---|
| Node 内置 WebSocket 不可用（钉钉 Stream 依赖） | 中 | 批次 4 前先 30 分钟实测；不可用则钉钉退化为 webhook 单向通知、对话由网页窗承担，核心价值不受损 |
| LLM 抽取偶发错 | 高 | 白名单+类型校验拦结构性错误；值错误靠草稿可见+人确认门+口头纠正 |
| 财务引擎迁移手滑 | 低 | 锚定六组数字放行门槛 |
| 钉钉企业应用审批慢 | 中 | 网页对话窗一期顶上，Agent 核心同一套 |
| DeepSeek Pro 模式未实测 | 低 | 仅影响后置 L3 文字辅助，不影响主线 |
