## 一、问题全景与修复方案（25 项）

### P0（鉴权绕过，必修）

**#1 附件下载端点无鉴权**
- 位置：server.js `/uploads/*` 分支（位于统一 auth 之前）
- 触发：未登录者持 URL 直接 GET 附件（含《项目贡献毛利率及成本预算表》等敏感经营数据），链接永不过期
- 修复：分支首行加 `if (!auth(req)) return send(res, 401, { error: '未登录' })`
- 验证：AV-01

### P1（必修）

**#2 agent/chat 先检查后写竞态（LLM 30 秒窗口写穿锁定单）**
- 位置：server.js 预算 chat 的 `UPDATE budgets SET fields=?`（无 status 条件）；评审 chat 的 `UPDATE reviews SET form_json`（同构）
- 触发：chat 请求 await extractFields（最长 30s）期间单据被 lock/submit，chat 返回后无条件覆盖已锁定/已提交数据，calc 与 settings_snapshot 失配
- 修复：两处 UPDATE 改条件更新 `WHERE id=? AND status='draft'`，`r.changes===0` 时返回 409 `'单据状态已变化(可能已锁定),本次对话字段未写入,请刷新'`
- 验证：AV-02（1.5s 慢桩并发）

**#3 存储型 XSS（两处渲染未转义）**
- 位置：public/app.js 技能①右列预算草稿预览 `<td>${AG.draft[f.k] ?? ''}</td>`；在线预算表 `value="${inp[f.k] ?? ''}"`
- 触发：预算 fields 的 str 字段（project_name/customer）含恶意 HTML → 支持组打开他人预算单即执行脚本（可调用归档/研判/改路由接口）
- 修复：两处补 `esc()` 包裹
- 验证：AV-03 + h_adv_check 浏览器断言

**#4 curl 子进程 stdin EPIPE → 进程崩溃**
- 位置：agent.js extractFields、notify.js postViaCurl 的 `cp.stdin.write(payload)` 后未监听 stdin error
- 触发：LLM 网关/钉钉 webhook 网络异常快速断开时 EPIPE 未捕获 → uncaughtException → 全站宕机
- 修复：两文件各加一行 `cp.stdin.on('error', () => {})`（EPIPE 吞掉，close 事件 reject 兜底）
- 验证：AV-04（断开桩连打 10 次服务仍在线）

**#5 judge 端点无状态门（草稿跳流程判灯/归档倒退）**
- 位置：server.js `/api/reviews/:id/judge`（只查角色不查状态）
- 触发：draft 单直接判灯（跳过提交门禁+前置评审）；archived 单判红倒退 returned
- 修复：加 `if (!['reviewing', 'judged'].includes(review.status)) return send(res, 400, { error: '仅前置评审中/已研判单据可触发研判(当前 ' + review.status + ')' })`
- 验证：AV-05

**#6 通知链接 localhost 硬编码（部署即失效）**
- 位置：server.js 7 处（notify reportLink 注入 + 红灯打回/研判完成/任务分发/绿灯发布/归档/退回 6 处 notifySafe 文案）
- 触发：部署到内网服务器后钉钉通知内链接全部指向用户手机自身
- 修复：config.json 增 `PUBLIC_BASE_URL`（默认空回落 localhost）；server.js 增统一 `reviewLink(id)` 函数读取配置，7 处全部改调它；部署时填 `http://<服务器IP>:8600`
- 验证：AV-10（桩断言 payload 含配置地址且不含 localhost）

**#13 演示账号与弱密码随包上线**
- 位置：server.js 种子用户（9 个 123456）；public/app.js 登录页 hint 块公开账号密码
- 修复（本期）：config.json 增 `DEMO_HINT`（默认 true 兼容开发测试）；`/api/me` 响应携带 `demo_hint`；前端 hint 块按其控制渲染；部署清单注明上线后立即改种子密码（附 SQL：`UPDATE users SET password_hash=? WHERE username=?`，密码哈希算法见 server.js 登录实现）
- 不改密码值的原因：10 套测试脚本硬编码 123456，改动面大；强制改密并入下阶段

### P2（精选 5 项，批次 B）

**#7 预算详情/对话留痕越权读**——GET /api/budget/:id 与 /messages 无 owner 检查（列表有隔离、评审侧有 403，此处漏配）。修复：加 owner/支持组/admin 检查（对齐 PUT）。验证 AV-08。

**#8 附件上传越权写**——任何登录用户可向任何单据传附件。修复：限申请人+支持组、限 draft/returned 状态。验证 AV-09。

**#9 退回后其余部门仍可 complete 触发自动研判**——A 部门退回后 B 部门提交打灯 → returned 单被自动研判成 judged。修复：complete 入口加 `review.status==='reviewing'` 检查。验证 AV-06。

**#10 complete 双击并发（重复研判+双通知+意见覆盖）**——检查在 await parseBody 前，双击两请求都通过。修复：改条件更新 `UPDATE tasks SET ... WHERE id=? AND status='pending'` 以 changes 判重。验证 AV-07。

**#14 前端交付明细行成本硬编码单价**——前端 995/320 与 settings 脱钩（财务调价后保存前显示错数）。修复：/delivery GET 响应增加 rd_price/prod_price（取 settings），前端 deliveryCalcRow 取用。

### P2/P3（记录不修）

- #11 前端渲染无错误兜底（401/500 卡"加载中"）——用户反馈驱动
- #12 spawnSync python 同步阻塞（大 Excel 解析期间全站卡顿 ≤60s）——单人使用可接受，多人使用后改异步 spawn
- #15 mergeDraft 空串语义（字段无法清空）#16 session 永不过期/无登出 #17 HMAC 非 timing-safe #18 parseBody JSON 失败应 400 #19 单价 `||` 应 `??` #20 意图词匹配过宽 #21 PUT 不带 form 清空表单 #22 辅助函数每请求重建/budgetChain O(n²) #23 无 CSP 头 #24 500 透传 e.message #25 budget 列表不认 admin——均内网单人场景低风险，记录待后续排期
