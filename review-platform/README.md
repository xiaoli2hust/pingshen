# 项目评审平台 MVP（第一阶段已上线）

把《项目评审管理规则-流程指引与评审表.xlsx》的 **信息收集 → 前置评审 → 红黄绿灯研判 → 归档** 四个环节线上化。
评审会（部门级/XO 级）仍线下开，本阶段先跑通线上主流程。

## 一、技术选型与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js 22（免安装版，E:\tools 或 workbuddy 托管） | 公司禁止装桌面应用，Node 免安装可跑 |
| 依赖 | **零 npm 依赖**（内置 `http` + `node:sqlite`） | 公司网络 npm 慢、GitHub 不通、无 C++ 编译器，零依赖最稳 |
| 数据库 | SQLite 单文件（`data/review.db`） | 免部署、免运维，备份=复制一个文件 |
| 前端 | 原生 HTML/JS 单页应用（`public/`） | 无构建步骤，改完即生效 |
| 附件 | 本地磁盘（`data/uploads/<单据id>/`），≤10MB | 内网部署无外部存储依赖 |
| AI 研判 | 规则引擎（本阶段）→ 预留 LLM 接入（下阶段） | 规则文件中的量化阈值全部可自动判定，LLM 做文字类条款辅助解读 |

## 二、工作流状态机（核心）

```
draft(草稿)
  │ 提交
  ▼
reviewing(前置评审中) ──任一评审人退回──▶ returned(退回修改)
  │                                        │ 修改后重新提交(轮次+1,任务重分发)
  │ 全部指标打灯完成                        │
  ▼ ◀──────────────────────────────────────┘
judged(已研判: 综合灯态+评审路径+AI报告)
  │ 红灯 → 申请人可修改后重新提交(回到 reviewing)
  │ 销售支持组归档
  ▼
archived(已归档, 材料+报告入库备查)
```

- **退回修改闭环**：前置评审人对任一指标可"退回"，填退回意见 → 单据回到申请人 → 修改 → 重新提交（轮次+1，旧任务作废留痕，新任务重新分发）。
- **自动研判**：最后一项指标打灯完成时，系统自动跑规则引擎出灯态，无需人工触发。

## 三、红黄绿灯研判逻辑（与规则文件一致）

1. **量化指标自动判**（按表单数值）：
   - 投标决策：分包占比(40%/70%)、测绘分包占比(40%)、毛利率(10%/0%)、合同金额(500万)、运维周期(3年)、指定供应商、签约转包次数(3/5层)、担保/竞业、结算方式(商票红线)
   - 售前立项：售前投入(10万/50万)、投入占比(5%)、实施周期(3个月)、签单时间(当前自然年)
   - 关键事项：交付成本变动(10万)、变更后毛利率(10%/0%)、变更后金额(500万)、超进度支付
2. **非量化指标取人工灯**：前置评审各部门打灯结果直接计入。
3. **综合灯态**：任一红→红（打回）；任一黄→黄（上会）；全绿→绿（免上会）。
4. **升级路由**：命中 XO 条件（运维>3年/毛利<0/金额≥500万/提前投入≥50万/分包≥70%/担保/竞业/指定供应商）→ XO 级；其中运维>3年、毛利<0、金额≥500万、提前投入≥50万、分包≥70% 五项额外标注"需推送杜总"。

## 七、与真实评审材料的对齐(2026-09-24 按 PL00008572 真实案例校准)

- **提交材料**：《项目贡献毛利率及成本预算表》为提交必传，**支持两种方式**：① 在线填写（见下）② 上传 Excel 附件，二选一
- **投标决策表单**：按真实提交版补齐字段——是否涉密、项目所在地省份(用于测绘分包红线)、产品售卖类型、推广激励对象/金额、预计回款时间、合同背靠背场景、确收方式及时间、是否涉及数据评审及数据类字段(实现方式/交付字段/合规审查)
- **前置评审指标**：投标决策 10 项(新增合规风险-合规BP、数据合规性-数据BP，新增角色 data1)；售前立项 5 项(新增客户过往合作信誉-财务BP)
- **研判规则修正**：签约转包次数=签约路径层数-1(真实案例 4 层路径=3 次转包→黄灯)
- **研判产出**：一键生成与线下一模一样的《项目风险评估报告》HTML(状态卡/项目基础信息/风险评估详述(仅红黄灯)/前置评审意见汇总/会议准备(参会人员+汇报准备+材料清单))，`/api/reports/<id>.html` 免登录可访问，便于推送领导
- **回归验证**：用真实案例数据(毛利 5.52%、转包 3 次)跑 test_flow.js，系统判定=真实结论(黄灯-部门级、2 项黄灯、无 XO)

## 七之二、预算表在线填 + AI 辅助填报(2026-09-24 二期)

- **在线预算表**：单据详情页 →「在线填写预算表」。只填成本项(分包/外包/灵活用工/销售费用/交付人天×单价/项目管理费等)，收入(合同÷1.06)、税金(1%)、销售人力(净签单×1727元/万)、激励(考核利润×7.7%)、贡献毛利/毛利率全部按财务口径**自动计算**，与 Excel 公式同口径
- **AI 识别填充**：把项目经理发的文字(微信/邮件/口头描述)粘贴进去 →「AI 识别填充」→ 大模型抽取人天、单价、费用自动填进表，人工核对后保存。接口 `POST /api/llm/fill-budget`(服务端代理，凭据不落前端)
- **数据打通**：研判引擎优先读取在线预算表的贡献毛利率(标注"取自在线预算表")，表单粗填值让位于预算表精算值
- **大模型配置**：已接入 **DeepSeek**（凭据存本机 `config.json`，不落前端）：`LLM_BASE_URL=https://api.deepseek.com`。界面可选 **Flash 快速版（deepseek-chat）/ Pro 增强版（deepseek-reasoner）**，日常用 Flash，口语化/复杂文本用 Pro
- **网络注意**：公司防火墙会重置 Node 原生 TLS 的出站连接，LLM 请求走系统 curl 转发（服务端内置，无需配置）
- 也可改回公司网关：config.json 换成 `ANTHROPIC_BASE_URL` 对应地址即可（公司网关目前回"不再支持个人工号"）
