项目评审线上化规划方案

基于《商机-项目关键节点评审管理流程指引 V1.0》——将 信息收集、前置评审、红黄绿灯评定 三环节线上化；评审会保留线下召开，但 关键风险在会前自动推送到各位领导，让会议只做决策、不做信息同步。

售前立项投标决策项目关键事项红黄绿灯会前风险推送

一、现状与痛点

表格多、分散

3 张信息收集表 + 1 张指标规则卡片（40+ 指标）+ 往上决策规则，全部靠 Excel 流转，版本难统一。

前置评审靠人肉

销售支持组逐一分发给交付/财务/采购/法务/合规，回收靠催，进度不可见，"规定时间内完成"无法考核。

灯态靠人工汇总

每周一人工汇总灯态、判断 XO 升级条件（11 项）和向上路由（14 条规则含杜总级），慢且易漏。

风险会上才暴露

领导在评审会上才第一次看到项目风险，会前无准备，会议变成"读材料"而不是"做决策"。

二、线上化目标与边界

线上化（本期做）

  • 信息收集：三张 Excel 表 → 在线表单，一次填报、全程复用
  • 前置评审：系统自动分发、各部门在线打灯 + 填意见、超时自动催办
  • 红黄绿灯评定：量化指标系统自动判灯，主观指标人工打灯，综合灯态与升级路由自动计算
  • 会前风险推送：黄/红灯项目的风险卡片，会前直达对应级别领导
  • 归档与台账：评审结论、决策文件线上归档，全程可追溯

保留线下（不做）

  • 部门级评审会（每周二）与 XO 级评审会（每周五）照常召开——领导多、需要当面质询与拍板
  • POC 投入维持邮件审批（规则明确不纳入红黄绿灯机制）
  • 法务涉诉等敏感信息仍由法务人工确认后录入（规则卡片已有此要求）
定位一句话：系统管"信息与判定"，会议管"决策与拍板"，推送管"会前到人"。

三、总体流程（线上化后）

1 信息收集销售/项目经理在线填报 Part A，系统按评审类型动态出字段，校验后提交
→
2 前置评审系统按指标责任矩阵自动分发，各部门并行打灯+意见，48h SLA 催办
→
3 智能评定规则引擎判定单指标灯态 → 综合灯态 → XO 升级 → 路由（部门级/XO/杜总）
→
4 风险预推送黄/红灯风险卡片会前推送给对应级别领导，绿灯留档、红灯打回
→
5 会议决策归档线下会照常开，结论线上录入、任务跟踪、自动归档

四、五大模块设计

M1信息收集 · 在线表单

三表合一，按类型切换

售前立项 / 投标决策 / 项目关键事项共用一套表单框架，选择评审类型后动态加载对应字段（如投标决策多出签约路径、分包金额、付款条件等 18 项；关键事项多出变更前后对比字段）。

字段级管控

下拉选项（业务线 G1/B2/G2、是否涉及测绘）、数值校验（金额、毛利率）、必填控制、附件上传（毛利率及成本预算表、客户审计报告、企查查记录等证据材料）。

数据复用

商机名称/代码关联 CRM 商机台账自动带出基础信息；同一项目售前→投标→关键事项三次评审信息继承，只填差异项。

M2前置评审 · 协同打灯

自动分发

提交后系统按"指标-责任部门"矩阵自动派单：FDE（技术可行性/交付资源/分包合理性）、财务BP（利润/付款/信用/关联交易）、采购BP（分包/指定供应商）、法务（签约路径/担保竞业/数据合规）、合规BP（测绘/甲导资质）。

在线打灯 + 意见

评审人对自己负责的指标逐项选择 绿 黄 红 并填前置评审意见；主观判断类指标（规则卡片标注"手动输入"的）必须人工打灯。

SLA 与催办

每环节 48 小时时限，看板实时显示"已评/未评"，超时自动钉钉提醒评审人，抄送销售支持组；彻底解决"规定时间内完成"无法落地的问题。

M3红黄绿灯 · 规则引擎

判定逻辑（与规则文件一一对应）

  • 单指标判定：量化指标（分包占比≥40%/70%、毛利率<10%/0%、合同金额≥500万、运维周期>3年、售前投入>10万/50万、关联交易>100万等）由系统按填报数值自动判灯；主观指标取前置评审人工灯态
  • 综合灯态：任一红 → 红（打回）；任一黄 → 黄（上会）；全绿 → 绿（免上会）
  • XO 升级：自动核对 11 项升级条件（运维>3年、指定供应商、意见不一致、毛利率<0%、金额>500万、提前投入>50万、分包>70%、担保、竞业、对外激励≥15%或≥30w、体系内规则外激励）
  • 向上路由：按"往上决策规则"14 条自动判定 部门级 / XO / 杜总 三级归宿

规则配置化（关键设计）

把"指标规则卡片"整张表做成后台可配置的规则库：阈值（如 500 万、40%）、灯态标准文案、责任部门、适用环节、是否公司级，全部做成配置项。

  • 规则调整（如阈值变化、新增指标）改配置即可，不需要改代码
  • 规则版本留痕，历史项目按当时版本判定，可回查
  • 已接入的"评审智能体"作为引擎的 AI 补充：对文字类材料（付款条款、签约路径描述）做辅助解读与判灯建议，最终灯态仍以规则+人工确认为准

M4会前风险预推送 本次需求核心

要素设计
推什么每个黄/红灯项目一张「风险卡片」：项目名称/金额/客户 → 综合灯态与评审路径（部门级/XO/杜总）→ 仅列出红黄灯指标（指标名、风险说明、责任部门意见）→ 触发的升级条件 → 会上需决策的问题清单。绿灯指标不推送，避免信息噪音。
推给谁按路由结果分级推送：部门级黄灯 → 部门级评审委员会成员；XO 级 → XO 评审委员会成员；触杜总级规则（运维>3年、毛利<0%、金额>500万、提前投入>50万、过单>70%）→ 加推杜总。销售支持组/企划办全量可见。
何时推两个波次：① 周一上午——系统自动汇总本周灯态，绿灯留档清单 + 红灯驳回通知 + 黄灯风险卡片首推（对齐现有"周一汇总邮件"动作）；② 会前 1 天——材料截止（会前 2 个工作日）后，推送最终版风险卡片 + 上会材料包链接。
什么渠道主推钉钉（已具备连接条件）：卡片消息直达到人，手机可览，点卡片进详情页；邮件同步归档版（对齐现行邮件留档要求）。
会后闭环会议结论（通过/有条件通过/驳回）线上录入后，自动回推给申请人与相关部门；有条件通过的约束条件生成待办任务跟踪。

M5会议支撑与归档台账

会上投屏看板

按会议议程排列本周黄灯项目，每项一页：风险卡片 + 各部门前置意见 + 需决策点，替代销售经理读 PPT。

结论线上化

决策结果当场录入，自动关联后续动作：通过后触发 PMS 项目建立/变更申请提醒（对齐现有评审后续要求），不通过且有预投入的触发 PMS 关闭提醒。

全程台账

项目从售前立项到关键事项的全部评审记录、灯态变化、决策文件归档一处，支持按区域/业务线/灯态统计（红黄灯率、平均评审周期、超时部门）。

六、周节奏（与现行机制完全对齐）

时点系统动作人工动作
提前 1 周在线提报入口开放，申请人自助预判灯态销售/项目经理填报
提前 2 个工作日材料提交截止，前置评审 SLA 到期自动催办各部门完成打灯
每周一自动汇总灯态：绿灯留档、红灯驳回通知、黄灯风险卡片首推领导销售支持组确认
每周二投屏看板 + 结论录入部门级评审会（线下）
每周五XO 级风险卡片提前 1 天加推（含杜总级事项）XO 级评审会（线下）

七、分期实施路线

P1 · 跑通主流程（4–6 周）

  • M1 在线表单（三类评审）
  • M2 前置评审分发 + 打灯 + 催办
  • M4 钉钉风险卡片推送（先按现规则半自动生成）
  • 基础台账

收益：摆脱 Excel 流转，领导会前收到风险

P2 · 智能判定（+4 周）

  • M3 规则引擎 + 规则配置后台
  • 综合灯态 / XO 升级 / 杜总路由全自动
  • M5 会上投屏看板 + 结论录入
  • 统计报表（红黄灯率、周期、超时）

收益：周一汇总从半天缩到一键

P3 · 集成与智能（持续）

  • CRM 商机 / PMS 项目数据打通
  • 评审智能体辅助解读合同条款类指标
  • 历史评审数据反哺规则优化

收益：填报减半，判定更准

八、落地注意事项

推送要"轻"

领导只收红黄灯、只收自己级别的项目，单项目卡片一屏看完；绿灯项目只进台账不打扰。这是推送机制能否被接受的关键。

规则维护责任

建议明确规则库归口（销售支持组维护 + 企划办审核），阈值调整走线上审批留痕，避免"规则改了、系统没改"。

敏感信息处理

法务涉诉详情、客户信用细节按现行规则人工确认后录入，推送卡片只显示结论性描述，详情需权限查看。

并行期安排

P1 上线后建议设 2–4 周 Excel 并行期，以系统数据为准回校 Excel，跑顺后停发表格。
